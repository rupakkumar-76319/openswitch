OpenSwitch is a coding agent that moves an app's OpenAI and Anthropic calls to NVIDIA Nemotron on Nebius Token Factory. It measures every Nemotron size, with and without thinking, on the app's own prompts, picks the cheapest configuration that keeps quality, rewrites the code, runs the tests and fixes what breaks.

How it works

Scan

The Python AST finds every OpenAI/Anthropic call, with its model and parameters.

PlanNemotron 3 Ultra · thinking

Purpose, output contract, rubric and risks for every call. Resolves models set in config files.

ResearchTavily + Nemotron 3 Super

Live prices for the current model and for Nemotron, plus the API differences that matter, with sources.

EvaluateNano · Super · Ultra × thinking on/off

Captures the app's real prompts with a fake SDK, runs 6 configs, checks each answer through the app's own code, Ultra judges.

RewriteUltra writes · AST checker verifies

Model ids, thinking flags, token headroom, config files and price tables, all mechanically checked.

Test & iteratepytest · Ultra debugs

Runs the repo's tests (or writes smoke tests). On a failure it fixes the code or moves that call to a stronger config.

Why it matters

  • Measured, not guessed. On refund-policy math, Nemotron Nano with thinking scored 9.2/10 while Super without thinking scored 3.3/10. Thinking is a choice per call, and OpenSwitch measures it.
  • Spends where it matters. When a much cheaper config narrowly misses, OpenSwitch doubles the sample for that call before deciding. In the Issue Digest run, that moved the call from Ultra to Nano with thinking: 10x cheaper, still passing.
  • Honest output. The report shows every configuration's score, flags calls that cost more after the switch, and lists the failure cases it found.
  • Nothing to trust blindly. You get a branch to review: a normal diff, a PR description and the test log.
